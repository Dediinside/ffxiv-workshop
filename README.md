# FFXIV Мастерская · 0.1.1

Отдельное Python-приложение с современным тёмным интерфейсом в локальном браузере. Объединяет Leve Planner, Market Scout и Рай перекупа: общий профиль профессий, рекурсивная себестоимость крафта, маршрут прокачки, спрос, сбор по расписанию, перепродажа и Telegram. Старые репозитории и программы не изменяются.

## Запуск

Нужен Python 3.10+. Для основного интерфейса Tkinter не требуется; он используется только в сохранённых регрессионных тестах старых окон. Запустите **start.bat**. При первом запуске создаётся собственная `.venv` и устанавливаются две закреплённые зависимости. Интерфейс открывается в браузере; расчёты выполняются локально на Python. Ничего не публикуется в интернет как сайт.

**start_demo.bat** запускает отдельный DEMO-профиль с искусственными ценами, без Telegram и рыночной сети. Эти результаты не являются торговыми рекомендациями.

Из терминала: `python bootstrap.py`; для демонстрации — `python bootstrap.py --demo`. `run.py` поддерживает `--profile`, `--port`, `--no-browser`. Повторный запуск открывает существующий экземпляр. Для завершения используйте кнопку **«Завершить приложение»** в боковой панели. Закрытие вкладки само по себе не останавливает мониторинг; сон ПК прерывает получение событий.

После установки здесь: `C:\FFXIVTools\ffxiv-workshop`, запуск через `C:\FFXIVTools\FFXIV Workshop.bat`. Настройки, кэши, история и защищённый токен находятся отдельно: `%LOCALAPPDATA%\FFXIVWorkshop`. При первом запуске копируются только не-секретные настройки профессий/расходов из Market Scout, если они есть; старый файл не меняется. Токен Telegram необходимо ввести заново.

## Общий профиль

Во вкладке **«Мои профессии»** укажите уровни всех ремесленников и сборщиков. Отключённая профессия не используется для изготовления заготовок. Книги, специалист и гарантированный HQ подтверждаются вручную. Уровни и параметры сохраняются между запусками и используются в каждом расчёте. Экипировку, craftsmanship/control, квесты и доступ к местам необходимо проверить в игре.

Мир продажи и область закупки общие и задаются в настройках. Для перекупа миры покупки автоматически ограничены DC мира продажи; стандартно Shiva/Light. Ограничения бюджета, фильтры и приоритет каждого инструмента задаются отдельно. Последние параметры форм сохраняются.

## Купить или изготовить заготовки

Сначала определяется потребность **всей партии**. Для каждого материала сравниваются покупка готового NQ и доступные рецепты его изготовления, затем рецепты раскрываются до базовых ресурсов. Учитываются все слоты ингредиентов, включая кристаллы, выход рецепта и целые рыночные стаки. Еда, зелья, ремонт и прочие фиксированные расходы начисляются на этап, где действительно есть крафт; стоимость каждого крафта учитывает и промежуточные операции. Расходники по рыночной цене также включаются в план. При переносе готовых остатков без нового изготовления эти расходы повторно не начисляются. Потребности общих материалов объединяются **до округления числа крафтов**. Остатки закупки/выхода переносятся по этапам маршрута, один стак не покупается повторно.

Пример: топор требует 2 стали по 10 gil и ручку по 10 gil — готовые материалы стоят 30. Если сырьё для одной стали стоит 5, а для ручки 2 и рецепты доступны, стоимость цепочки составляет **12 gil**. Настоящий расчёт добавляет налоги, кристаллы и заданные расходы. Заготовку недоступной профессии программа купит. Если ни покупку, ни доступную цепочку нельзя оценить, сумма остаётся неизвестной, а не нулевой.

Стоимость и список изготовления строятся из **одного выбранного плана**. В Pre-craft / Final Items попадают действительно выбранные крафты; если предмет выгоднее купить готовым, он остаётся в закупке. Текстовый импорт Artisan/Teamcraft передаёт количество предметов по английским именам; HQ/NQ, recipe ID и профессия не кодируются. При нескольких рецептах проверьте импорт. Полный маршрут выполняйте по этапам, поскольку рецепты откроются позже.

Поиск сравнивает покупку всей потребности материала с изготовлением всей потребности. Смешанная покупка части и крафт остатка одного материала не оптимизируются. До 4 000 состояний на оценку: при достижении лимита показывается предупреждение и лучший найденный полностью оценённый вариант. Это не обещание глобального минимума. Циклические рецепты исключаются. Сбор сырья автоматически не считается бесплатным.

## Прокачка

Раздел **Leves · 5 уровней** сохраняет привычный расчёт следующего рубежа. **Маршрут прокачки** — самостоятельный раздел от текущего до желаемого уровня. EXP вводится целым числом внутри уровня; пустой бюджет означает отсутствие лимита. Есть покупка/крафт, HQ/NQ, приоритет закупки или allowances, расходы, gil-награды и перенос EXP.

Рецепты прокачиваемой профессии проверяются по уровню **начала этапа**, другие — по сохранённому профилю. EXP крафта не добавляется. Маршрут выбирается по этапам до открытия новых leves; это не доказанный минимум среди всех возможных последовательностей. Бюджет сравнивается с закупкой заранее, награды не финансируют её. Неполный маршрут явно показывает неизвестную стоимость до цели и причину остановки.

## Производство и сбор

Ищутся товары доступных профессий, затем проверяются состоявшиеся продажи на выбранном мире. По умолчанию нужен спрос ≥1 шт./день, ≥3 сделки за 7 дней, последняя продажа ≤72 часа. Большая цена без продаж не становится рекомендацией. Расчёт учитывает рекурсивные заготовки, налоги, еду, зелья, ремонт, дорогу, прочие затраты и стоимость каждого крафта **включая промежуточные**. Расходники по ID могут оцениваться по рынку отдельно от фиксированных затрат; не учитывайте один расход дважды.

Расписание временных/ephemeral узлов, личный урожай за окно, скорость сбора и приманки сохраняются. В подробностях товара можно записать личный замер по ID. Неизвестные время/условия и приманки не превращаются в гарантированную прибыль за час. Рыболовные условия и конкретное место проверьте в игре.

Предварительный и подробный лимиты видны в форме. Каталог обходится ограниченными выборками: пустой результат не означает проверку всего рынка. Цена продажи ограничивается историей и конкурентами. CSV и кликабельные ссылки доступны в таблицах.

## Перекуп, горячие события и история

Поле **«Последняя продажа ≤ часов»** задаёт допустимую давность последней состоявшейся продажи на домашнем мире отдельно для HQ/NQ (1–168 часов; по умолчанию 72). После суточного простоя можно использовать 48–72 часа. Выбор сохраняется при запуске поиска и применяется в обычном, периодическом и горячем режимах. Это не поле «Срок продажи ≤ дней», которое оценивает будущую реализацию стака.

Обычный поиск, периодический поиск и WebSocket-режим **«Горячие предложения»** используют проверенные алгоритмы Рай перекупа: целые стаки одного DC, отдельные HQ/NQ, спрос на мире продажи, конкуренты, налоги, дорога, прибыль и падение цены. Проверяются новые для программы версии и снижение цены; событие Universalis не доказывает, что предмет только что выставили в игре.

Перед Telegram конкретный стак перепроверяется. Повторы сохраняются; успешные уведомления резервируют общий бюджет с запасом, объём товара и минутный лимит между обычным/горячим поиском. Покупки пользователя и инвентарь не отслеживаются; лимит сбрасывается вручную после проверки покупок. Telegram настраивается в новом профиле; токен защищён Windows DPAPI и не возвращается в браузер после сохранения.

Строки горячих находок остаются в таблице и истории: зелёный — недавно проверено, жёлтый — с проверки прошло 90 секунд, красный — событие снятия/изменения. Жёлтый не доказывает исчезновение товара, красный не доказывает вашу покупку. Сохранённая цена относится к моменту находки. История показывает последние 500 совпадений по всему архиву, имеет поиск и копирование цены.

## Данные персонажа: WorkshopBridge

В `bridge/release` включены DLL и manifest для **Dalamud API 15**; в `bridge` — исходники. Плагин собран против установленного Dalamud, без ошибок. Проверка внутри игрового клиента не выполнялась. Он экспортирует уровни/EXP профессий, домашний и текущий мир; имя персонажа и Content ID не записываются. Gil, allowances, инвентарь, книги и экипировка пока не экспортируются.

1. В Dalamud откройте Settings → Experimental → Dev Plugin Locations и добавьте путь к `bridge/release/WorkshopBridge.dll`; загрузите этот dev-плагин через `/xlplugins`. Это способ из [официальной документации Dalamud](https://dalamud.dev/faq/getting-started/). Он не опубликован в официальном каталоге.
2. Войдите персонажем и выполните `/workshop` для одного снимка или `/workshop auto` для обновления каждые пять секунд. Повтор `/workshop auto` отключает обновление; после перезапуска плагина оно отключено по умолчанию.
3. В Мастерской включите **«Подхватывать локальный файл персонажа»** и сохраните профиль. Программа проверяет файл каждые 10 секунд. Либо выберите файл и нажмите «Импортировать снимок». При нестандартном `--profile` используйте ручной импорт.
4. Снимок старше 10 минут не импортируется. Книги/HQ остаются вашими ручными настройками. Плагин читает данные через [IPlayerState](https://dalamud.dev/api/Dalamud.Plugin.Services/Interfaces/IPlayerState/), не автоматизирует игру и не отправляет данные в сеть.

Для сборки: .NET SDK 10, Dalamud API 15 и `dotnet build bridge/WorkshopBridge.csproj -c Release`. При смене API Dalamud нужна новая сборка; не отключайте проверку совместимости.

## Данные, сеть и проверка

Встроены закреплённые игровые каталоги из xivapi/ffxiv-datamining: 1 120 leves, 9 580 рыночных рецептов, расписания сбора и 16 845 marketable предметов. Снимок от 17 сентября 2026; в настройках есть обновление каталога. Цены и история поступают через Universalis. Они обновляются игроками, полнота и задержка не гарантируются. При ошибках старые рыночные цены не подставляются; сумма может быть неизвестной.

Общий ограничитель REST — 5 запросов/секунду для всех режимов, включая повторные попытки. Рыночные кэши и история раздельные по нужному формату, находятся в новом профиле. Локальный сервер слушает только 127.0.0.1; API требует случайный ключ сессии и проверяет Origin/Host. Внешние CDN и шрифты не требуются. При запуске проверяется стабильный релиз только **нового** GitHub-проекта.

`python check_tests.py` запускает независимые наборы тестов. Проверены экономики старых модулей, рекурсивная цепочка, выходы/общие материалы, недоступные профессии/книги, отсутствующие цены, остатки, цикл, отмена, профили/импорт и доступ к локальному API. В интерфейсе проверены основные расчёты в DEMO; реальные Telegram-сообщения не отправлялись. Детали в `VALIDATION.md`.

Игровые названия принадлежат Square Enix. Источники: [xivapi/ffxiv-datamining](https://github.com/xivapi/ffxiv-datamining), [Universalis](https://docs.universalis.app/), [Dalamud](https://dalamud.dev/).
